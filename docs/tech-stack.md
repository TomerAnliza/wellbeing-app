# סטאק טכנולוגי מומלץ — אפליקציית ה־Wellbeing

- **תאריך:** 7 בספטמבר 2026
- **סטטוס:** המלצה של הסוכן הראשי לפי הנחיית תומר ("מבוסס Supabase +
  הזדהות, השתמש בספריות כגון Next"). **טרם אושר סופית** — מועמד טבעי
  לחוות דעת של צחי לפני תחילת מימוש.
- **משרת את:** [spec-wellbeing-mvp-screens.md](spec-wellbeing-mvp-screens.md).
  כל בחירה כאן נגזרת מדרישה שם; בחירה שאין לה דרישה באפיון אינה נכנסת.
- הגרסאות המדויקות ייקבעו בזמן ההתקנה מול התיעוד הרשמי, לא כאן.

## ליבה

| שכבה | בחירה | נימוק |
|---|---|---|
| Framework | **Next.js** (App Router) | צד שרת + לקוח באפליקציה אחת; ניתוב לפי קבצים מתאים למבנה `/app/habits/{habitId}` ו־`/app/check-in/{occurrenceId}`; Server Components מפשטים שליפת נתונים מאומתת בצד השרת |
| בסיס נתונים | **Supabase** (PostgreSQL) | הישויות באפיון (`profiles`, `habits`, `habit_schedules`, `habit_occurrences`, `reminder_consents`, `reminder_deliveries`, `body_measurements`) עם מפתחות זרים אמיתיים; Row Level Security על כל טבלה כדי שמשתמש א' לא יראה נתוני משתמש ב' |
| הזדהות | **Supabase Auth** דרך `@supabase/ssr` | אימייל וסיסמה, אימות דוא"ל, שחזור סיסמה, sessions בעוגיות ו־PKCE. `@supabase/ssr` הוא הדרך הרשמית לחבר Auth ל־App Router |
| Client SDK | `@supabase/supabase-js` | הלקוח הרשמי. ה־secret key נשאר בצד השרת בלבד |
| תזמון | **Supabase Cron** (pg_cron) + **Edge Functions** | יצירת מופעי פעילות עתידיים ואיתור מופעים שהגיע זמן התזכורת שלהם, בלי שרת נוסף |
| תזכורות | **WhatsApp Cloud API** של Meta | תבנית מאושרת עם קישור עמוק ל־`/app/check-in/{occurrenceId}`; webhook מעדכן סטטוס משלוח. תלות ליבה לפי האפיון, ונבדקת מקצה לקצה לפני יתר הממשק |

## ספריות מומלצות

| צורך | ספרייה | נימוק |
|---|---|---|
| עיצוב | **Tailwind CSS** | תמיכת RTL מובנית עם logical properties (`ps-` / `pe-` / `ms-` / `me-`); סטנדרט בפרויקטי Next |
| רכיבי UI | **shadcn/ui** (מבוסס Radix) | רכיבים נגישים שמועתקים לפרויקט וניתנים להתאמה מלאה לעיצוב שייבחר; ניווט מקלדת ותוויות לאייקונים מגיעים מובנים |
| טפסים וולידציה | **react-hook-form + zod** | הרשמה, שאלון ההקמה ועריכת הרגל; zod נותן סכמת ולידציה אחת שמשמשת גם בצד השרת |
| גרפים | **Recharts** | גרף העמודות השבועי וכרטיסי ה־KPI במסך ההתקדמות; מספיק לטווח של ארבעה שבועות |
| תאריכים ואזורי זמן | **date-fns + date-fns-tz** | "עכשיו בשעה המקומית של המשתמש" הוא לב מנגנון התזכורות; אזור הזמן נשמר בפרופיל |
| CAPTCHA | **Cloudflare Turnstile** דרך ההגנה המובנית של Supabase Auth | האפיון דורש CAPTCHA והגבלת קצב בהרשמה, כניסה ושחזור. **לא אומת עדיין** אילו ספקים Supabase תומך בגרסה הנוכחית; לבדוק בתיעוד הרשמי בזמן ההתקנה |
| מזהים | `crypto.randomUUID()` מובנה | בלי תלות מיותרת למה שהדפדפן ו־PostgreSQL כבר יודעים |

## מה במפורש לא צריך

- **ORM נפרד (Prisma/Drizzle)** — Supabase client מספיק לשבע טבלאות;
  שכבה נוספת רק תסבך פרויקט הדגמה למתחילים
- **ניהול state גלובלי (Redux/Zustand)** — Server Components + state
  מקומי מכסים את הצורך
- **ספריית fetch (TanStack Query)** — שליפות בצד השרת דרך Supabase client
- **ספריית גרירה ושחרור** — אין באפיון סידור ידני של פריטים
- **Web Push / PWA** — ערוץ התזכורות באפיון הוא WhatsApp בלבד. אם יתווסף
  ערוץ גיבוי, הוא ייכנס באפיון קודם ורק אז כאן

## נקודות זהירות

1. **RTL** — לוודא `dir="rtl"` ב־root layout ושימוש ב־logical properties
   של Tailwind; גרפים של Recharts דורשים בדיקת כיווניות צירים בעברית
2. **RLS** — מדיניות נפרדת ל־select / insert / update / delete על כל טבלה,
   עם `auth.uid() = user_id`; נדרשות בדיקות שליליות שמוכיחות שמשתמש א'
   אינו ניגש לנתוני משתמש ב'
3. **שליחה כפולה** — constraint ייחודי ב־`reminder_deliveries` על
   (מופע, סוג תזכורת) לפני הקריאה ל־WhatsApp, לא אחריה
4. **Webhooks** — אימות חתימה, מניעת replay, ואיסור על כתיבת מספרי טלפון
   או נתוני גוף ללוגים רגילים
5. **Open redirect** — יעד החזרה אחרי התחברות מוגבל לכתובות פנימיות בלבד
6. **נתוני דמו** — נטענים כ־seed ב־SQL migration, לא בקוד האפליקציה
